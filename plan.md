# ТЕХНИЧЕСКОЕ ЗАДАНИЕ И ПЛАН РЕАЛИЗАЦИИ ПРОЕКТА "VIBECITY" (Афиша мероприятий)

> **Актуальное уточнение (по требованию заказчика):** проект разворачивается как группа
> Docker Compose `vibecity` из трёх контейнеров — `frontend`, `backend`, `db`. Демо-данные
> локализованы под Беларусь: города Минск, Гомель, Брест, Витебск, Гродно, Могилёв;
> телефоны `+375`, почты `vibecity.by`, цены в белорусских рублях. Актуальное описание
> инфраструктуры и запуска — в README.md.

## 0. Общая архитектура и стек
*   **Стек:** 
    *   Frontend: React 18, TypeScript, Vite, Tailwind CSS (стилизация), Zustand (стейт-менеджмент), React Router v6, Axios (HTTP-запросы), React Query (кэширование).
    *   Backend: Node.js, TypeScript, Express.js, Prisma ORM, JWT (авторизация), Bcrypt (хэширование паролей), Zod (валидация данных).
    *   Database: MySQL 8.0.
*   **Инфраструктура:** Единый Docker-контейнер на базе Debian/Ubuntu. Внутри контейнера запускаются: MySQL (в фоне), Node.js сервер (раздает API и статику React).

## 1. Проектирование Базы Данных (Строго по логической схеме)
Создаем `schema.prisma`. Добавляем поле `role` в Пользователя (для доступа к админке) и `image_url` в Мероприятие.

**Сущности и атрибуты:**
1.  **User (Пользователь):** `id` (PK), `lastName` (Фамилия), `firstName` (Имя), `patronymic` (Отчество), `phone` (Телефон), `email` (Email), `password` (Пароль), `role` (ENUM: USER, ADMIN).
2.  **Organizer (Организатор):** `id` (PK), `name` (Название), `contactPerson` (Контактное лицо), `phone` (Телефон).
3.  **Place (Место):** `id` (PK), `city` (Город), `name` (Название), `address` (Адрес), `capacity` (Вместимость).
4.  **Tag (Тег):** `id` (PK), `name` (Название тега), `type` (Тип).
5.  **Event (Мероприятие):** `id` (PK), `organizerId` (FK), `placeId` (FK), `tagId` (FK), `name` (Название), `date` (Дата), `time` (Время), `description` (Описание), `category` (Категория), `imageUrl` (Ссылка на картинку). *(Связи: 1 Организатор -> N Мероприятий; 1 Место -> N Мероприятий; 1 Тег -> N Мероприятий)*
6.  **Review (Отзыв):** `id` (PK), `userId` (FK), `eventId` (FK), `text` (Текст), `rating` (Оценка 1-5), `date` (Дата). *(Связи: 1 Пользователь -> N Отзывов; 1 Мероприятие -> N Отзывов)*
7.  **Gift (Подарок):** `id` (PK), `name` (Название), `description` (Описание), `type` (Тип), `status` (Статус).
8.  **Promocode (Промокод):** `id` (PK), `giftId` (FK), `code` (Номер промокода), `status` (Статус). *(Связь: 1 Подарок -> N Промокодов)*
9.  **Ticket (Билет):** `id` (PK), `userId` (FK), `eventId` (FK), `promoId` (FK), `seatNumber` (Номер места), `status` (Статус), `qrCode` (QR-код). *(Связи: 1 Пользователь -> N Билетов; 1 Мероприятие -> N Билетов; 1 Промокод -> N Билетов)*

3. Этап 2: Разработка API (Backend)

Каждый контроллер возвращает JSON и обрабатывает ошибки через централизованный middleware.

Слой Auth (Авторизация):

POST /api/auth/register — прием ФИО, email, пароля. Хэширование пароля, создание пользователя с ролью USER.
POST /api/auth/login — проверка пароля, выдача JWT-токена (срок жизни 24ч).
Middleware authMiddleware — проверяет заголовок Authorization: Bearer <token>.
Middleware adminMiddleware — проверяет, что role === 'ADMIN'.
Слой Events (Мероприятия) - Публичный доступ:

GET /api/events — получение списка. Обязательно: поддержка query-параметров ?category=...&city=...&tagId=...&search=...&page=1&limit=10 (пагинация и фильтрация).
GET /api/events/:id — детальная информация (join с таблицами Place, Organizer, Tag, а также подтягивание всех Review).
Слой Events (Мероприятия) - Для Организаторов/Админов:

POST /api/events — создание (валидация через Zod: дата в будущем, цена не отрицательная и т.д.).
PUT /api/events/:id — обновление.
DELETE /api/events/:id — удаление.
Слой Tickets (Билеты):

POST /api/tickets/buy — создание билета. Генерация уникального UUID для поля qrCode. Проверка валидности промокода (если передан promoId). Списание доступных мест (вместимость).
GET /api/tickets/my — список билетов текущего авторизованного пользователя.
Слой Reviews (Отзывы):

POST /api/events/:id/reviews — оставить отзыв (оценка от 1 до 5). Проверка, что пользователь купил билет на это мероприятие.
DELETE /api/reviews/:id — удаление отзыва (только админ или автор).
Слой Админки (CRUD для справочников):

GET/POST/PUT/DELETE /api/admin/places
GET/POST/PUT/DELETE /api/admin/organizers
GET/POST/PUT/DELETE /api/admin/tags
GET/POST/PUT/DELETE /api/admin/gifts
GET/POST/PUT/DELETE /api/admin/promocodes
4. Этап 3: Разработка Фронтенда (Frontend)

Инициализация: npm create vite@latest frontend -- --template react-ts. Установка tailwindcss, react-router-dom, axios, zustand, @tanstack/react-query, lucide-react (иконки), qrcode.react (для генерации QR-кодов).
Настройка Axios: Создание инстанса с базовым URL. Настройка интерцептора (если токен есть, добавляем в headers; если приходит 401 — разлогиниваем).
Глобальный стейт (Zustand): useAuthStore (хранит данные пользователя, токен, методы login/logout).
Верстка и Компоненты (UI):

Layout: Header (логотип VibeCity, навигация, кнопка профиля/входа), Footer.
EventCard: Карточка мероприятия (Картинка imageUrl, Название, Дата, Место, Теги, Кнопка "Подробнее").
FilterSidebar: Боковая панель с фильтрами (Категория, Город, Дата).
Modal: Универсальное модальное окно (для покупки билета, авторизации).
Страницы (Pages):

HomePage: Вывод сетки EventCard с использованием React Query и пагинацией. Сверху баннер.
EventDetailPage: Большая картинка, полное описание, инфо о месте и организаторе. Кнопка "Купить билет" (открывает модалку выбора места и ввода промокода). Ниже секция отзывов (список + форма добавления).
ProfilePage: Вкладки "Мои билеты" (карточки с QR-кодом, который можно показать на входе) и "Настройки профиля".
OrganizerDashboard: Форма добавления нового мероприятия (выбор из выпадающих списков мест, тегов, организаторов — данные тянутся с бэка) и таблица своих мероприятий.
AdminDashboard: (Доступ только для role === ADMIN). Вкладки с таблицами: Пользователи (бан/разбан), Мероприятия (модерация, удаление), Отзывы (удаление), Справочники.
LoginPage / RegisterPage: Формы с валидацией полей (длина пароля, формат email/телефона).
5. Этап 4: Docker (Единый контейнер)

Задача: упаковать всё в один образ, чтобы пользователь запускал docker run или docker-compose up и всё работало.

Dockerfile (Multi-stage build):

Stage 1 (Сборка фронта): Берем node:20-alpine. Копируем frontend/, ставим зависимости, билдим (npm run build). На выходе папка dist.
Stage 2 (Сборка бэка): Берем node:20-alpine. Копируем backend/, ставим зависимости, генерируем Prisma клиент (npx prisma generate), компилируем TS в JS (npm run build).
Stage 3 (Финальный образ): Берем debian:bookworm-slim (чтобы без проблем поставить настоящий MySQL).

Устанавливаем mysql-server, curl.
Устанавливаем Node.js 20 (через Nodesource).
Копируем собранный бэкенд из Stage 2.
Копируем dist из Stage 1 в папку backend/public (чтобы Express раздавал статику).
Копируем entrypoint.sh и даем ему права на исполнение (chmod +x).
Открываем порт 3000 (или 8080).
entrypoint.sh (Скрипт запуска внутри контейнера):

Инициализация директорий MySQL (если пусто).
Запуск MySQL в фоне (mysqld_safe &).
Цикл ожидания, пока MySQL запустится (проверка mysqladmin ping).
Применение схемы БД: npx prisma db push.
Запуск сидинга (наполнение данными): node dist/seed.js.
Запуск основного сервера: node dist/index.js (он слушает порт и раздает и API, и фронтенд).
docker-compose.yml: (Для удобства проброса портов 3000:3000 и volumes для БД mysql_data:/var/lib/mysql, чтобы данные не терялись).
